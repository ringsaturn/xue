# Changing the format

The format has three implementations that must agree byte for byte. Read
`.claude/rules/cross-implementation.md` first.

## 1. Classify the change

| Change | Readers affected | Deploy order |
|---|---|---|
| New optional metadata block (like `band`, `producer`, `aerosol`) | all three validate it when present; old readers ignore it | one-sided: data may ship any time |
| New required field, new `schemaVersion`, container version bump | all three must implement it **and keep reading every older version** | **shell first**, then data |
| Manifest schema widened | `manifest.py`, `encode/manifest.rs`, `manifest.ts` | **shell first** |
| Encoding change with no schema change (codebook, predictor, chunking) | encoders only; golden fixtures move | either, but goldens regenerate |

A reader rejects an over-declared `schemaVersion`. Write the *lowest*
version that fits, so each file keeps exactly one valid encoding.

## 2. Change, in this order

1. **Spec**: `docs/format.md` (container, metadata), `docs/zarr-profile.md`
   (store), or the manifest section, describing the new rule normatively.
2. **Python encoder** (the reference): `xuebuild/binconvert.py::build_metadata`,
   `binformat.py`, `zarrstore.py`, `manifest.py` as applicable.
3. **Python reader**: `binformat.py::_parse_metadata`.
4. **Rust**: `rust/xue/src/format.rs` (byte layout only),
   `decode/metadata.rs`, `zarr.rs`, and the native encoder under
   `rust/xue/src/encode/` (`metadata.rs`, `binformat.rs`, `manifest.rs`).
5. **Frontend**: `web/src/manifest.ts::parseBundleMetadata` and the manifest
   validator; `web/src/zarr/shard.ts` for store changes.
6. **Fixtures**: `.venv/bin/python tests/prepare_bin_fixture.py` (Rust
   golden), the registry fixtures if an identity or codebook moved,
   `tests/prepare_web_fixture.py` is regenerated by Playwright's setup.

## 3. Verify

```sh
make test                 # rust golden + python (incl. native parity) + vitest
make encoder-rust-test    # native encoder byte identity (needs GDAL + libclang)
npm run build             # typecheck
```

Add a test that an *old* file still decodes, and one that a malformed new
field is rejected by every validator.

## 4. Ship

Commit the spec, the code in all implementations and the fixtures together.
If the change is shell-first, deploy Pages (`deploy-pages.yml`) before any
publish workflow writes the new shape: merge the reader side to `main`
first. If the native encoder changed, the encoder side goes through a
`release/0.N` branch (the `release` skill) and reaches `main` together with
its relocked wheel. Scheduled workflows pin `XUE_ENCODER=native`, so they
write the new shape only after that.
