# Working in this repo

## Environment

- Use `.venv/bin/python` (created by `uv sync`), never the system
  interpreter. The Makefile's `PYTHON` picks it automatically.
- `make check` verifies the toolchain (GDAL, zstd, node, wasm-pack).
- The frontend needs `make wasm` first.
- `plans/` is a private local symlink that may be absent. Never reference it.

## Tests

| Scope | Command |
|---|---|
| Everything except e2e | `make test` |
| One Python module / case | `.venv/bin/python -m unittest tests.test_bin -v` / `tests.test_bin.Case.test_x` |
| Rust decoder (+ golden) | `make test-rust` or `cd rust && cargo test -p xue golden` |
| Native encoder parity | `make encoder-rust-test` (needs GDAL + libclang) |
| Web unit | `npx vitest run tests/web/manifest.test.ts` |
| Typecheck + build | `npm run build` |
| e2e | CI only (`make test-e2e` needs `npx playwright install chromium`) |

Fixtures: Playwright's are synthetic (`tests/prepare_web_fixture.py`, no
network, no GDAL). The Rust golden is built by `tests/prepare_bin_fixture.py`.
Product goldens are regenerated by `tests/prepare_{tc,airport,sounding}_golden.py`.
Regenerate a fixture only on purpose, and say so in the commit.

## Commits

- Subjects are lowercase and imperative, with an optional scope prefix:
  `web:`, `ci:`, `docs:`, `fix:`, `aurora:`, ….
- Keep commits small and single-purpose. Stage files explicitly: other
  sessions may share the worktree.
- Never commit generated or fetched data (see `.gitignore`).

## Documentation

- `docs/*.md` are normative specs. Change them with the code, in the same
  commit.
- `docs/contribution/` holds developer knowledge (how and why). Update it
  when you change a mechanism it describes. Do not duplicate it in comments.
- Code comments say *why* something non-obvious holds. They do not narrate
  history ("since 0.26…", "earlier versions…"): that belongs in git.
- `README.md` is user-facing; keep it short.
