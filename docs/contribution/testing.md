# Testing

```sh
make test               # Rust decoder + Python encoder + web unit tests
make test-rust          # regenerates the golden fixture, then cargo test
make encoder-rust-test  # native encoder unit tests + byte-identity golden (needs GDAL, libclang)
make test-e2e           # Playwright (needs `npx playwright install chromium`)
wasm-pack test --headless --chrome rust/xue-wasm   # the decoder in a real browser
```

Single tests:

```sh
.venv/bin/python -m unittest tests.test_bin -v
.venv/bin/python -m unittest tests.test_bin.SomeCase.test_method
cd rust && cargo test -p xue golden
npx vitest run tests/web/manifest.test.ts
npx playwright test tests/e2e/app.spec.ts -g "scrub"
```

## What holds what

- **Python** (`tests/test_*.py`): codebooks, modulo-256 residuals,
  container structure and its rejection paths (truncation, out-of-range
  offsets, overlaps, gaps, nonzero padding, cyclic dependencies, checksum
  failures), the manifest and pointer contracts, every source's crop
  fixture through both encoders, the Zarr export, the STAC documents and
  the point products against committed goldens.
- **Encoder parity**: `tests/test_native.py` compares every artifact of
  one build through the `xuepy` wheel against the reference pipeline, byte
  for byte. `tests/test_assemble.py` holds a split build and a top-up
  identical to a whole one.
- **Rust**: `rust/xue/tests/golden.rs` decodes fixtures built by
  `tests/prepare_bin_fixture.py` byte-identically, plus mutation fuzzing.
- **Registry fixtures** (`tests/fixtures/*-registry.json`) hold the three
  implementations to one set of ids, identities and codebooks; regenerate
  them when a source's inputs widen.
- **Web** (`tests/web/`, Vitest): manifest validation, the Zarr reader
  (every frame and series identical to the wasm bundle reader), the
  variable table, URL state, discovery files.
- **Browser** (`tests/e2e/`, Playwright): synthetic fixtures built by
  `tests/prepare_web_fixture.py` (no network, no GDAL); download,
  streaming, playback, scrubbing, error recovery, and the store-only path.

Fixture provenance and regeneration are in
[`tests/fixtures/README.md`](../../tests/fixtures/README.md). Goldens are
regenerated by the `tests/prepare_*_golden.py` scripts after a deliberate
change (the tc and sounding ones need `bufr_dump`).

## CI

`.github/workflows/test.yml` runs the Python (3.12 and 3.14), Rust, web
and browser jobs on every push and pull request except prose-only changes
(`**.md`, `docs/**`). On `release/**` branches the Python job builds the
wheel from the tree instead of installing PyPI's, since the encoders there
run ahead of the published wheel (see [releasing](releasing.md)).
